## 补丁 5【必改·会误伤广播】idle 模式下 `last_boundary_confirmed` **恒为 False**

### 事实（全部已核对到行）

| 位置 | 内容 |
| --- | --- |
| `core/rcon.py:141` | `self.last_boundary_confirmed: bool \| None = None`（三态，设计良好） |
| `core/rcon.py:280` | 每条命令事务开始**先置 `False`** ✓ |
| `core/rcon.py:362` | 只有「命令响应包 + 哨兵」按序到齐才置 `True` ✓ |
| `core/rcon.py:365-375` | **idle 降级分支：置 `False` 后仍返回已收到文本** |
| `docs/VERIFY_v0.22.5.md:57` | 明确记录：「在 `end_mode=idle` 下该标志一旦 `False` 就**再无机会回到 True**」 |

### 后果

修订实施单 §二-4 要求：

> 边界未确认时，任何空响应都不能当成功……`boundary_confirmed != True` 也不能判定为可靠成功。

在 **idle 模式**下 `boundary_confirmed` **恒为 `False`**，于是：

```
tellraw 空输出 → boundary=False → unknown
→ 广播 / 喊话 / 全屏喊话 集体报「结果未知」
```

而**现状**（`main.py:1750`）：

```python
await rcon.command(cmd)
return f"已在服务器内广播：{message}"      # 完全忽略输出，直接报成功
```

→ 本次修复会让 **idle 模式下的广播从「成功」变成「结果未知」**，属于**功能倒退**
（虽然更诚实，但用户会以为广播坏了）。

### 补法

对**幂等静默命令**（`tellraw` / `say` / `title`）在边界未确认时，**不要用「结果未知」**——
消息确实发出去了，只是无法保证送达完整性。建议：

- 单独一态 `sent_unconfirmed`；或
- 措辞改为「已发送（响应边界未确认；如需保证完整性请把 `rcon_end_mode` 设回 `sentinel`）」
- **绝不显示「失败」**

### 对照测试

- idle 模式 + `tellraw` 空输出 → **不得**报「失败」，**也不得**报「结果未知」（应为「已发送·边界未确认」）
- sentinel 模式 + `tellraw` 空输出 → `success`

## 补丁 6【必改·照字面实现会吞掉所有成功】

修订实施单 §三「优先级顺序」：

```
…
6. 无法判断 → unknown
7. 明确成功反馈 → success
```

**第 7 步排在第 6 步之后。** 若「无法判断」被实现为「没命中任何错误模式」，
则**成功文本会先被第 6 步吞成 `unknown`，第 7 步永远不可达**。

### 修正顺序（成功判定必须早于 unknown 兜底）

```
1. RCON 异常                          → unknown
2. 空响应                             → 按命令类型 + 边界判定
3. Unknown command. Type "/help"      → failed
4. 明确解析错误                        → syntax_error
5. 其他明确失败文本                     → failed
6. 明确成功标记                        → success      ← 提到 unknown 之前
7. 兜底（无任何标记）                   → unknown
```

## 补丁 7【建议·精度】`[` 单独作特征太吵

修订实施单 §七 的命令特征里含 `[`。但 `[` 是**选择器语法**，在正常简单命令里到处都是：

```
kill @e[type=item]
tp @p[tag=foo]
gamemode creative @a[team=red]
```

这些全会被误判进复杂流水线 —— 白跑一整套 Agent，白烧 token。

而本次出问题的命令：

```
netherite_sword[enchantments={levels:{…}}]
```

**本来就含 `{`**。→ **去掉裸 `[`，只留 `{`**，捕获能力不减，噪音大降。

### 对照测试

- `kill @e[type=item]` → 仍允许 simple
- `give X netherite_sword[enchantments={…}]` → 强制 complex

## 补丁 8【建议·命名】白名单的判据是「幂等」，不是「静默」

修订实施单 §二-1 把这组命令称为「静默命令」。但白名单里的
`time` / `weather` / `gamerule` / `gamemode` / `difficulty`
在 vanilla 里**都是有回显的**：

```
Set the time to Day
Set the weather to clear
Set difficulty to Easy
```

它们**并不静默**。真正让「空输出 = 成功」成立的属性是**幂等**（重复执行无额外副作用），
与是否有回显无关。

建议改名为**「幂等白名单」**，并在注释里写明判据是幂等性 ——
否则实现者会按「静默」这个错误标准增删名单。
