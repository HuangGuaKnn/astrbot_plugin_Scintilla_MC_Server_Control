# 常见问题

[返回 README](../README.md) · [界面效果](gallery.md) · [配置详解](configure.md) · [使用指南](usage.md) · [版本支持](compatibility.md) · [常见问题](faq.md)

安装与使用中容易踩到的坑。

### 1. 工具都说「物品词典不可用」？

服务端目录没配好。到 WebUI「设置」页填 `server_dir` 并保存 —— 保存即重算指纹与词典，不用重载插件。

### 2. 换了服务端，知识库会自己切吗？

不会。指纹变化时插件只在 WebUI 弹全屏提醒并高亮不匹配的预设，是否搬家由你确认（预设支持复制 / 移动 / 绑定到本服务端）。

### 3. AstrBot 和服务端不同机？

打开「异地 RCON 模式」：只走 RCON，依赖本地文件的功能（物品词典、知识库、事件播报、版本探测、进程指标）全部按设计禁用，并在界面上写明原因。

### 4. 能控制基岩版 / 代理端吗？

只走 RCON 的标准能力。凡是不经 RCON 的功能（日志播报、词典、指纹）都要求能读到服务端目录。

### 5. 为什么内存 / CPU 显示不出来？

这两项依赖 `psutil`，缺失时插件会自动降级（不报错，只是不显示）。装一下即可：`pip install psutil`。

### 6. 停用某个工具后 AI 还看得见它吗？

部分工具（如 `mc_workflow`）模型仍会看到，但调用时会收到导航提示，转而使用其他工具，不会真的执行。

### 7. `mcs` 前缀和 AstrBot 唤醒词冲突？

指令组的前缀跟随 AstrBot 的唤醒词设置。若你把唤醒词改成了别的，指令也相应变化。

### 8. 能同时接多个服务端吗？

一个插件实例目前只能连一个 RCON 目标。需要多服的话装多份实例，未来可能会适配（插件目录复制一份、改配置即可）。

### 9. UI 截图里的数据是假的吗？

那是演示数据，用来展示界面形态。真实数据来自你的 RCON 连接与服务端目录扫描。

### 10. 设置页提示「RCON 已自动降级」是什么意思？

说明插件连续多次**没能确认响应边界**（服务端不回应结束哨兵，或哨兵抢在命令响应之前到达）。
为了不让你彻底用不了，它会自动退回 `idle` 静默窗口模式 —— 代价是「响应是否读完」重新变成猜测，服务端分包间隔偏大时长响应可能被截断。
排查完在设置页点「重建 RCON 连接」即可回到配置的方式（默认 `sentinel`）。

### 11. 非管理员为什么有些 `execute` 写法会被拒绝？

黑名单策略下，非管理员用 `execute` 时插件会**按 Minecraft 语法**解析出真正的子命令再判权限：
嵌套超过 8 层、子命令或条件边界判不出来的写法（例如 `if items` / `if function` 这类参数个数不固定的条件）一律**拒绝**，而不是「猜不出来就放行」。
管理员不受此限制；白名单策略下非管理员本来就不能用命令工具。

### 12. 升级后所有走 LLM 的功能都报 `'dict' object has no attribute 'model_dump_for_context'`？

这是**插件 v0.23.3 及更早**在 **AstrBot 4.27.x** 上的兼容问题，与你的 RCON、服务端目录都无关。
特征是：`mcs` 指令照常能用，但**走模型**的能力（知识库检索、工作流决策、反馈润色）一起报错，
而且报错位置在 AstrBot 核心内部，很容易误判成上游的问题。

原因：插件注入的提示块是 dict，而 4.27.x 的核心对每个内容块都会调
`model_dump_for_context()`（字段文档写的是「支持 dict 或对象」，实现只认对象）。
**升级插件即可**（v0.23.5 起新旧核心都能消费）；只想临时处置，升级 AstrBot 核心也行。
注意更新一点的核心已经补了 dict 兼容分支，所以这类问题**不一定能在本机自测里复现**。

### 13. 服务端回 `Unknown or incomplete command, see below for error` 和 `<--[HERE]`，是「没这条命令」还是「我写错了」？

**从 1.21 起，这两种情况回的是同一句话** —— 服务端不再用文案区分「命令不存在」与「语法 / 参数写错」，
只在正文下面用 `<--[HERE]` 标出它解析不下去的位置。
插件的识别因此也不看这句话：它拿命令名去查内置允许表（`core/java_commands.py` 的 `COMMAND_LEVELS`），
不在表里的按「未知命令」处理 —— 黑名单策略下默认拒绝，确属自装模组的命令可在设置里打开「允许未知命令（模组 / 整合包自定义）」。
这类回执按「语法 / 参数写错」处理（可纠错重试）；但若真相是命令不存在，重试只是白跑一轮，所以先按下面三步自查：

1. **看 `<--[HERE]` 插在哪** —— 它标的是服务端第一个解析不下去的分词。贴着命令名本身 = 命令名不对；贴着后面的参数 = 命令存在，是参数写法不对。
2. **砍到只剩第一段单独发一次**（例如只发 `give`）：第一段就报这句 = 你这台服务端上确实没有这条命令（模组没装 / 版本不支持，重试徒劳）；第一段能过、加参数才报 = 语法问题，按你这代版本改写法。
3. **对一下版本** —— 1.21 线的物品要用组件写法（`netherite_sword[enchantments=…]`，各小版本的差异见[版本支持](compatibility.md)），1.20.4 及更老的 NBT 写法在这里会被拒；`attribute` 必须带操作词（`attribute … get`），缺词报的也是这句。

> 这句提示**不等于**「物品 / 属性不存在」，它只说明服务端没接受这条写法。
