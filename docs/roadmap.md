## 探索中

| 方向 | 想解决什么 | 卡在哪 |
| --- | --- | --- |
| 受控 Web 命令面板 | 在 WebUI 里执行**白名单内**的运维命令（保存世界、广播、天气） | 白名单怎么划、危险度怎么分级 |
| 常用世界操作 | 天气 / 时间 / 保存 / 广播 的一键按钮 | 与上一条大概率是同一套机制，可能合并成一个 |
| 封禁详情读法 | 异地 RCON 模式下读不到服务端目录，封禁的「原因 / 时间 / 操作者」只能显示「未知」 | 目前没找到不依赖服务端目录的读取方式 |

## 明确不做

| 项 | 为什么不做 |
| --- | --- |
| 数字物品 ID 反查 | 1.13 之前的老 ID 表与 mod 冲突严重，误判的代价高于收益 |
| 同时对接多个 RCON 目标（多后端矩阵） | **难度过大**：不是配置多几项的问题 —— 每个后端都要独立判定世代、独立维护连接与重连、独立处理命令语法差异，出错时的归因成本成倍上升；投入产出比不成立 |
| 在 WebUI 里执行任意命令 | 等于把 RCON 权限摊成网页输入框，风险不可控 |
| 玩家背包 / 物品栏读写 | 不属于「服务器管控」的范畴，且各模组写法互不兼容 |
