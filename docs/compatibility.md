# 版本支持

[返回 README](../README.md) · [界面效果](gallery.md) · [配置详解](configure.md) · [使用指南](usage.md) · [常见问题](faq.md)

这一页记录**实测结论**：每个 Minecraft 版本上，插件生成了什么、拒绝了什么、依据是什么。
表里的每一行都来自真实服务端（完整服务端目录 + RCON 实连 + 正反样例对照），不是纸上推演。
数据截至 **v0.23.7（2026-10-06）**。

> **一句话结论**：`1.8.9` ~ `1.21.11` 共 **10 台服务端已实测**，命令生成 / 拒绝行为与设计模型一致；
> 其中 1.13 以下不自动生成物品类命令是**预期行为**（原因见下），不是故障。

## 一、实测矩阵

### 1. 逐版本结论

「实测深度」三档口径：

- **断代对全验** —— 正样例（应放行）+ 负样例（应硬拦）+ 手动补发路径，全对照走完；
- **科目验** —— 点火 + RCON 体检 + 插件工具链语体自证（工具回包跟着站点走）+ 部分专项科目；
- **基线台** —— 日常开发与实际使用所在的版本。

| 版本 | 载体 | 实测深度 | 自动命令生成 | 物品数据写法 | 实测要点 |
| --- | --- | --- | --- | --- | --- |
| **1.8.9** | 原版 | 断代对全验 | ⛔ 物品类拦 / 白名单放行 | 预扁平化（不生成） | `title` 自 1.8 起可用 ✓；**原生自带 RCON**（比印象中早得多）；全角括号洗白门在此版本生效 |
| **1.12.2** | Forge 14.23.5.2864 | 断代对全验 | ⛔ 物品类拦 / 白名单放行 | 预扁平化（不生成） | `give` / `execute` 硬拦并说明原因；`time` / `tellraw` / `title` 正常；手动路径补发可用 |
| **1.13.2** | 原版 | 断代对全验（样本最厚） | ✅ | NBT：`{Enchantments:[…]}` | 旧式 NBT `summon` ✓ / `data get` ✓ / 版本探测 ✓ / RCON 单包上限活体站 |
| **1.14.4** | 原版 | 科目验 | ✅ | NBT | 聊天 / 标题 / 长标题显示层三连正常（人眼验收）；1.14 断代的后侧；单包上限活体站 |
| **1.16.5** | Forge 36.2.42 | 科目验 | ✅ | NBT | `#RRGGBB` 颜色**原样精确**（颜色门控分水岭右端）；回包语体进入「of a max **of**」世代 |
| **1.20.1** | Forge 47.4.23 | 基线台（长期在用） | ✅ | NBT | 物品 / 附魔 / NBT 全路径的日常验证版本 |
| **1.20.4** | 原版 | 科目验 | ✅ | NBT（1.20.4 及以下写法） | 点火 + RCON 体检 + 回包格式取样；1.20.5 组件断层的前侧 |
| **1.20.6** | 原版 | 科目验 | ✅ | 物品组件：`[enchantments={…}]` | 点火 + RCON 体检 + 回包格式取样；`sweeping` 旧附魔名的最后一代 |
| **1.21.1** | NeoForge 21.1.255 | 断代对全验 | ✅ | 物品组件 | `sweeping_edge` 新名 ✓ / 旧名被拒 ✓ / 无前缀属性被拒 ✓ / 现代路径自动生成 `give` ✓ |
| **1.21.11** | 原版 | 科目验 | ✅ | 物品组件 | 1.21 线最后一版；单包上限活体站；1.21.2 属性去前缀的后侧 |

### 2. 各世代回包格式（解析器容差）

工具要读懂服务端的回包，而回包文案**按世代变脸**。下面是实测取样：

| 命令 | 1.8.9 | 1.12.2 | 1.13.2 | 1.14.4 | 1.16.5 | 1.20.x | 1.21.x |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `list` | `0/20 players online:` | 同左 | `…0 of a max 20 players…` | 同左 | `…0 of a max **of** 20 players…` | 同左 | 同左 |
| `time query daytime` | `Time is N` | 同左 | `The time is N` | 同左 | 同左 | 同左 | 同左 |
| `seed` | 无括号 | 无括号 | （未采样） | 有括号 | 有括号 | 有括号 | 有括号 |
| `give` 回执 | — | `Given [Item] * 1 to Player` | `Gave 1 [Item] to Player` | — | — | — | 同 1.13.2 |

- 分代结论：`list` / `seed` / `time` 三处**同代变脸**，都发生在 **1.13（扁平化）那一代**；
- `list` 里的第二个「of」出现在 **1.14.4 → 1.16.5 之间**（1.15 / 1.16 代），已由卡位实测收紧。

### 3. 物品词典的可读性

| 服务端形态 | 词典能力 |
| --- | --- |
| 有 `mods/`（Forge / NeoForge / Fabric） | 扫各 mod 的 jar，拿到**精确 ID**，中英文模糊搜索 |
| 1.13+ 的 Paper / Spigot / 原版（无 `mods/`） | 退化为从服务端原生 jar 读**原版英文**物品表（1.21 线实测 1500+ 条）；中文搜不到，模组物品仍需要 `mods/` |
| 1.13 以下 | 读不到原版物品表（实测 0 条）——旧版物品映射在 1.0.0 路线图上 |

## 二、语法分水岭与实测状态

真正的「硬分水岭」只有下面这几条 —— 它们会让同一条命令在某个版本上直接解析失败。
其余版本差异（回包文案、显示效果）由插件做容差，不影响命令能否执行。

| 分水岭 | 层面 | 内容 | 实测 |
| --- | --- | --- | --- |
| **1.13** | 命令语法 | 命令图重写 + 资源 ID 扁平化：`give` 取消 data 位、NBT 改贴物品 ID、旧 `execute @p ~ ~ ~` 废弃、`entitydata` → `data` | ✅ `1.13.2` 与 `1.12.2` 正反对照（同一条 `give`：一台拦、一台生成） |
| **1.13** | 函数体系 | `/function` 从存档 `functions/` 迁到数据包体系 | 未实测（插件当前不生成 `/function`，仅登记能力） |
| **1.14** | 命令语法 | `execute if/unless` 条件子命令首次出现 | 未实测（`1.14.4` 台已就位） |
| **1.20.2** | 物品 NBT 字段 | 药水等物品的部分 NBT 字段改名 | 未实测（按外部核验方裁决收录，**插件未真机验证**） |
| **1.20.5** | 物品格式 | NBT `{…}` → 物品组件 `[…]`（含 `CustomModelData` / `AttributeModifiers` / `display.Name` 改名） | 未实测（`1.20.4` / `1.20.6` 两侧台已就位） |
| **1.21** | 附魔 ID | `minecraft:sweeping` → `minecraft:sweeping_edge` | ✅ `1.21.1` 正反样例（新名生效 / 旧名报错） |
| **1.21.2** | 属性 ID | 去分组前缀：`generic.movement_speed` → `movement_speed` | ◐ `1.21.1` 上验过「无前缀会被拒」；后侧形态待 1.21.2+ 实例 |

## 三、尚未实测 / 推断区

| 项目 | 现状 | 补齐条件 |
| --- | --- | --- |
| **Paper / Spigot 载体** | 未点火。无 `mods/` 的退化路径（从原生 jar 读原版物品表）只有间接样本 | 需一台 Paper 服务端 |
| **Fabric 载体** | 未点火（`mods/` 扫描逻辑同构，但未验） | 需一台 Fabric 服务端 |
| **无断代的中间版本**（1.15 / 1.17 / 1.18 / 1.19 / 1.20.2 等） | 按分水岭推导，未逐台实测 | 出现问题时点杀 |
| **年号制版本**（Mojang 已改 26.x 制，`1.21.11` 是 1.21 线末版） | 插件未建模 | 需要时再评估，暂不设上限守卫 |
| **1.13 以下的完整支持**（`legacy_preflatten` 档案：数字物品 ID / data 映射、`ench` 数字附魔） | 在 1.0.0 路线图上。当前一律**明确拒绝**，而不是猜着生成一条必然失败的命令 | 需真实世界的旧版命令样本 |

## 四、实测中的已知边界

这些是巡礼时实打实撞到、并已收进代码的边界 —— 列出来，是为了遇到时不必重新怀疑人生。

| 现象 | 适用范围 | 处理 |
| --- | --- | --- |
| **RCON 单包上限**：命令体（UTF-8）超过 **1446 字节**（整包 1460）服务端会静默断连，回包是 0 字节 | **全世代同构**（1.8.9 ~ 1.21.11 反编译逐版核对，`1.13.2` / `1.14.4` / `1.21.11` 活体三站实测同界） | 插件侧做文本预算：渲染后超限自动降级单色 / 截断，并在日志留痕 |
| **长消息 + JSON 渐变**膨胀（约 35 字节/字），放大了上一条的风险 | 老版本尤甚 | 按字节预算裁决：超线一律落回单色（「预算第一」）；短消息渐变照常真下发 |
| **全角括号「（」**在 1.8.x 客户端被映射到贴右半格，长文本被左右剪掉 | **仅 1.8.x 线**（1.9.4 / 1.14.4 / 1.16.5 实测全干净，1.9+ 全部豁免） | 发送给服务端的文本自动洗成半角（可开关，只动文本、不动命令参数） |
| **空服广播**：1.12.2 静默成功，1.16.5+ 回 `No player was found` | 消息投递类命令 + 通配选择器 | 识别为「消息已发出、暂无接收者」，不再误判失败；点名目标与语法错误照旧判失败 |
| **跨零点日志轮转**：`latest.log` 每日轮转，启动行被压进归档 → 版本探测突然变「未知」（保守档） | 原版 / Forge 通用，长期不重启服务端的服务器 | v0.23.7 起回退扫归档日志（`.log.gz`，头部只读、单文件损坏不牵连） |
| **颜色能力门控**：`#RRGGBB` 需 1.16+；更老版本回退到 16 色名近似，并在日志留痕 | `< 1.16` | 默认档自动回退；格式化符号简写（如 `§6`）全世代可用，写入时归一为色名 |
| **属性命令须显式操作词**（`attribute … get`），缺词报的是 `Unknown or incomplete command` | 1.21.1 实测 | 提示语义已写进工作流约束（该报错 ≠ 元素不存在） |

## 五、怎么复现这些结论

想自己验一台 → 一套最小样本就够：

1. 服务端起好、开 RCON（`enable-rcon=true`）；
2. 插件设置页填 `server_dir` + RCON 信息（异地模式则手填 `server_version_override`）；
3. 查一遍版本探测：服务器页应显示**正确版本 + 来源（服务端文件探测）**；
4. 正样例：`time set day` / `say` / `title` / `list`；
5. 负样例：按上表分水岭，发一条**邻世代**写法（例如 1.13.2 上发旧 `execute @p ~ ~ ~`），应被**明确拒绝并说明原因**；
6. 带数据命令：`give <你> diamond_sword 1`，再看附魔写法是否与你那代一致。

结果与我们不同？欢迎带上服务端版本 + 加载器 + 原话 + 插件实际执行 / 拒绝的命令原文到
[Issues](https://github.com/HuangGuaKnn/astrbot_plugin_Scintilla_MC_Server_Control/issues) 反馈 —— 版本相关的异常正是这份矩阵最需要的燃料。
