基础 · 连接与安全

RCON 连接

异地 RCON 模式AstrBot 与服务端不在同一台机器 · 只映射了 RCON 端口
已开启：服务器目录可以留空，插件只走 RCON 下发指令。作为交换， 物品词典 / 知识库 / 聊天桥接 / 服务器事件播报 / 版本探测 / 进程指标 这些依赖服务端本地文件的能力会按设计禁用 —— 下方对应区块会被标记为不可用并写明原因， 终端、mcs 状态与决策 AI 也会明确告知，不会假装可用。
读取服务器日志、mods/ 或 plugins/ 目录的根路径；服务器事件转发、词典与知识库均依赖它。保存时会做结构校验（logs/、libraries/、server.properties、eula.txt、启动脚本、服务端 jar 任一即可），不像服务端根目录会拒绝保存。

权限与安全

两个模式的开关与说明统一放在下方 「命令工具 · 白名单 / 黑名单」 窗口里。管理员 admin_ids 不受策略限制，永远可用全部能力。
mcs 封禁 未填写理由时使用

命令工具 · 白名单 / 黑名单

本策略只管「命令工具」；想限制「喊话」请到「指令」分组关闭「喊话对全员开放」。 改动后记得点「保存全部设置」。
被拒绝时不只是「拦住」，还会让决策 AI 明白这是权限判定、不是用法问题（详见下方 「拦截即终局 · 闸门强化」）。

拦截即终局 · 闸门强化

光「拦住」还不够：还要让决策 AI 明白这拦得没有商量余地。否则它会以为是自己用法不对， 改个参数、换个工具接着硬试。
权限前置提醒（注入提示词） 非管理员发起对话时，提前把「哪些命令工具会被直接拒绝 + 有哪些替代方式」写进系统提示词，从源头劝退
拦截后会话闩锁 同一会话一旦被权限闸门拦下，有效期内再调命令类工具会被直接短路，不再触碰闸门与服务器，并提醒 AI 立刻停手
默认 300（5 分钟），到期自动解除。
被拦时返回的文案已明确标注「这是权限判定，不是参数/用法问题，重试与换工具都无效」； 参数误封装（AI 把参数多套一层 {"arguments": {...}}）也会被自动拆开后再判定， 不会再出现「工具没跑起来却被当成用法错误」的情况。

服务器事件播报（游戏 → 会话）

服务器事件转发监听服务器日志并记录最近的指定事件，并转发到指定会话

播报：聊天内容
选类型后填 QQ 号或群号即可，自动拼成 平台ID:消息类型:会话ID；也可直接粘贴完整标识。

推送需四道闸门齐备：总开关「服务器事件转发」→ 上方对应的类型开关 → 该会话勾选的事件 → 目标会话存在。 总开关关闭时，会话侧怎么勾都不会推送。

聊天桥接（游戏 → 会话）

桥接总开关玩家在游戏内发送带符号消息即转发到会话
游戏内直接打 !123 或全角 ！123，中间无需空格；全角/半角始终兼容；一个符号都不添加则转发全部聊天
区分大小写关闭：符号大小写不敏感，Q 与 q 等价；开启后必须大小写完全一致
同样只填号码即可。推荐：在目标会话里发送 mcs 桥接 自动绑定，免手填。
占位符：{player}=玩家名，{message}=正文
游戏内转发回执玩家聊天转发至群聊成功后，将以仅该玩家可见的形式在游戏内发送一条确认信息

语义增强检索加嵌入向量通道
（仅推荐大型长期运行服务器开启）
重排序精排候选池交 Rerank 逐条重排
检索引擎与增强检索怎么选
检索引擎：BM25 按「字序」匹配，查「黄铜」不会捞出「铜黄」，权重自动压低「通用 / 方案 / 规则」这类套话，长条目也不会靠字数霸榜 —— 实测结果精确率 20.5% → 58.6%（2.9 倍）、无关条目减少 82%，5000 条规模检索 6.3ms → 2.0ms。切换后点「保存全部设置」即时生效，无需重载插件。
旧版：中文按单字、英文按整段做子串命中，字面与历史结果完全一致，但容易连锁误召回（查「满配一把枪」会捞出一堆含「配 / 方 / 案」的条目）。仅在需要与历史检索结果完全对齐时才选。
语义增强检索：只建议大型服务器启用 —— 开启后提问可以「换种说法」问，例如问「后台连不上了」，也能捞到库里那条「RCON 连接失败排查」。本机实测（438 条语料 / 24 组查询）：Hit@1 75.0% → 87.5%、Hit@6 79.2% → 100%（口语改写型 Hit@6 58.3% → 100%），无关条目误召回同步归零。
代价：每次检索多一次嵌入调用（约 300~500ms 延迟）；建库时每条约一次，只算新增 / 改动过的条目，结果落盘缓存，不会重复烧。
前提：先在 AstrBot「服务提供商」里添加一个 Embedding 模型（如 Qwen3-Embedding-4B）。没有的话开关开了也不生效 —— 检索会安静退化成纯 BM25，不报错；条目少的小库用 BM25 已经够准，故默认关闭。
重排序精排：库大了、问法杂了之后，「召回」难免把真正对的条目排到中游 —— 精排（Cross-Encoder）把候选池逐条与提问重新比对，看的是真实相关性，能把该在前面的提上来。开启后检索变成两段式：先召回 20 条候选，再精排取前几条。
与语义增强检索独立：没有 Embedding 模型也能单开（只对 BM25 召回池精排）；两者同开就是「BM25 + 向量 RRF 召回 → rerank 精排」的完整三段式。
代价 / 前提：每次检索多一次重排 API 往返（约几百毫秒），小库不值这份延迟，故默认关闭；需先在「服务提供商」里添加一个 Rerank 模型（如 vllm_rerank / Qwen3-Reranker-8B），没配置时开关开了也不报错 —— 检索安静退化为召回顺序。
模型回落：上面两个下拉只列 AstrBot 里已加载的模型（配置了但没启用、或加载失败的不会出现）；留空 = 自动使用第一个（与不指定时行为完全一致）；指定的模型哪天被删了，检索会自动回落到第一个并在保存时提示，不会因此失效。
生效时机：词典与知识库在插件启动时构建；改 server_dir 或「物品词典 / 学习型知识库」这两项开关会在保存时就地重建（无需重载插件），其余开关即时生效。
